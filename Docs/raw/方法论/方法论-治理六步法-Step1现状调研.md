# Step 1：现状调研（Week 1-2）

## 📌 目标
全面摸清企业数据管理的现状，**识别痛点、短板和风险**，为后续方案设计提供事实依据。

## 📋 详细过程

### 1.1 项目启动会（第1天）

**参与者**：项目发起人、数据治理负责人、各业务部门代表、IT代表

**议程**：
1. 明确项目目标、范围、时间表
2. 介绍数据治理的基本概念和价值
3. 明确各方职责和配合事项
4. 确定访谈计划和资料需求清单

**关键动作**：
- [ ] 准备项目启动PPT（含项目背景、目标、计划、团队）
- [ ] 发送会议邀请，确保关键人员到场
- [ ] 会议纪要当天发出，明确Action Items

---

### 1.2 资料收集（第1-3天）

**收集内容清单**：

| 资料类型 | 具体内容 | 提供方 |
|:--------|:--------|:------|
| 组织架构 | 部门设置、岗位职责、汇报关系 | 人力/综合部 |
| 系统清单 | 核心业务系统、数据仓库、报表系统清单 | IT部门 |
| 数据架构文档 | 系统架构图、数据流向图、接口文档 | IT部门 |
| 现有制度 | 数据管理制度、安全制度、标准规范 | 数据管理部门 |
| 历史问题 | 数据质量问题记录、监管处罚记录、投诉记录 | 质量/合规部门 |
| 监管要求 | EAST/1104/金融基础数据等报送要求 | 合规/统计部门 |
| 外部评估 | DCMM评估报告、审计报告、第三方评测 | 数据管理部门 |

**关键动作**：
- [ ] 制定《资料需求清单》并发送给各责任方
- [ ] 设定资料提交截止时间（建议3个工作日内）
- [ ] 对收到的资料进行编号和登记

---

### 1.3 访谈调研（第3-7天）

**访谈对象清单**：

| 对象 | 人数 | 访谈重点 | 时长 |
|:-----|:----:|:--------|:----:|
| 数据治理委员会成员/高管 | 2-3人 | 战略期望、资源支持、考核机制 | 1h |
| 数据管理部门负责人 | 1-2人 | 现有工作、困难、规划 | 1.5h |
| 业务部门负责人 | 每部门1人 | 数据使用痛点、对标准的期望 | 1h |
| 业务部门骨干（Steward候选） | 每部门2-3人 | 日常数据操作、质量问题细节 | 45min |
| IT部门负责人 | 1-2人 | 系统现状、技术架构、改造能力 | 1h |
| IT开发骨干 | 3-5人 | 系统细节、数据接口、技术难点 | 45min |
| 合规/统计部门 | 1-2人 | 监管要求、报送痛点、数据口径 | 1h |

**访谈提纲模板**：

```
【通用问题】
1. 您部门目前使用哪些系统？主要用什么数据？
2. 目前数据方面最大的痛点是什么？（举例说明）
3. 是否遇到过因数据问题导致的业务损失或监管问题？
4. 您认为数据标准应该由谁来制定？谁来执行？
5. 如果推行数据治理，您希望得到什么支持？最担心什么？

【高管加问】
6. 您对数据治理项目的期望目标是什么？
7. 愿意投入多少资源（人力/资金/时间）？
8. 是否可以将数据质量纳入部门KPI？

【业务骨干加问】
9. 您日常工作中，哪些数据字段最容易出问题？
10. 同一数据在不同系统不一致时，以哪个为准？
11. 是否清楚自己操作的数据会影响哪些下游？
```

**关键动作**：
- [ ] 提前发送访谈提纲，让被访者准备
- [ ] 访谈时做好记录（录音+笔记，征得同意）
- [ ] 访谈当天输出《访谈纪要》，发送给被访者确认

### 1.4 系统走查（第5-8天）

**走查内容**：

| 走查项 | 具体内容 | 目的 |
|:------|:--------|:----|
| 核心系统 | 登录系统，查看数据录入界面、字段设置 | 了解数据源头的数据质量 |
| 数据仓库 | 查看ODS/DWD/DWS层表结构 | 了解数据加工链路 |
| 报表系统 | 查看核心报表的数据来源和口径 | 发现口径不一致问题 |
| 元数据管理 | 如有元数据平台，查看数据资产目录 | 了解元数据管理成熟度 |
| 质量监控 | 如有质量监控平台，查看检核规则 | 了解质量监控覆盖度 |

**走查记录表**：

| 系统名称 | 走查日期 | 走查人 | 发现的问题 | 严重程度 | 备注 |
|:--------|:-------:|:-----:|:----------|:-------:|:---:|
| | | | | | |

### 1.5 数据质量抽样检查（第6-9天）

**抽样方法**：
- 选择3-5张核心表（如客户表、借据表、还款表）
- 每张表随机抽取100-1000条记录
- 对关键字段进行质量检查

**检查维度**：

| 维度 | 检查内容 | SQL思路 |
|:-----|:--------|:-------|
| 完整性 | 关键字段空值率 | `COUNT(*)` vs `COUNT(字段)` |
| 准确性 | 格式合规率（手机号、身份证） | `RLIKE` 正则匹配 |
| 一致性 | 同一客户在不同系统的信息是否一致 | 跨表JOIN对比 |
| 及时性 | 数据更新延迟 | 对比业务时间 vs 系统时间 |
| 唯一性 | 主键重复 | `GROUP BY` + `HAVING COUNT(*) > 1` |

**抽样检查结果表**：

| 表名 | 字段名 | 检查项 | 样本数 | 问题数 | 问题率 | 严重程度 |
|:-----|:-----:|:-----|:-----:|:-----:|:-----:|:-------:|
| customer | mobile | 格式合规 | 1000 | 85 | 8.5% | 高 |
| customer | id_no | 非空 | 1000 | 12 | 1.2% | 中 |
| loan | amount | 大于0 | 1000 | 3 | 0.3% | 低 |

### 1.6 现状评估（第8-10天）

**评估框架（参考DCMM）**：

| 能力域    | 当前成熟度 | 主要短板 | 优先级 |
| :----- | :---: | :--- | :-: |
| 数据战略   |       |      |     |
| 数据治理   |       |      |     |
| 数据架构   |       |      |     |
| 数据标准   |       |      |     |
| 数据质量   |       |      |     |
| 数据安全   |       |      |     |
| 数据应用   |       |      |     |
| 数据生命周期 |       |      |     |

**评估方法**：
- 对标DCMM 3级/4级要求逐项打分（1-5分）
- 结合访谈、资料、走查、抽样结果综合判断
- 每项短板给出改进建议

### 1.7 报告编制与评审（第9-14天）

---

## 📦 Step 1 交付物清单

### 交付物1：《项目启动会议纪要》

**内容**：
- 会议时间、地点、参与人
- 项目目标、范围、时间表（确认版）
- 各方职责分工
- Action Items（责任人+截止时间）

**格式**：会议纪要模板（Word）

---

### 交付物2：《资料收集登记表》

**内容**：
- 资料名称、提供方、收到日期、缺失项

**格式**：Excel表格

---

### 交付物3：《访谈纪要》（每一场一份）

**内容**：
- 访谈时间、地点、访谈人、被访人
- 核心观点（用被访者原话+提炼）
- 发现的问题和痛点
- 达成的共识
- 待跟进事项

**格式**：统一模板（Word）

**关键要求**：
- 访谈当天输出
- 发送给被访者确认（避免误解）
- 被访者确认后归档

---

### 交付物4：《系统走查记录表》

**内容**：
- 走查的系统清单
- 每张表的字段结构
- 发现的问题清单

**格式**：Excel表格

---

### 交付物5：《数据质量抽样检查报告》

**内容**：
- 抽样方法和范围
- 各维度检查结果（附SQL）
- 问题分布分析
- 改进建议

**格式**：Word报告 + Excel数据附件

**关键要求**：
- 附检查SQL（可复制复用）
- 用图表展示问题分布（柱状图、饼图）
- 问题按严重程度排序

---

### 交付物6：《数据治理现状调研报告》★ 核心交付物

**内容结构**：

```
一、执行摘要（2页，给高管看）
   1.1 调研背景和方法
   1.2 核心发现（3-5个）
   1.3 关键建议（3-5条）
   1.4 预期收益

二、组织现状（3-5页）
   2.1 组织架构和数据责任分布
   2.2 现有数据管理团队和能力
   2.3 数据治理委员会运作情况
   2.4 RACI矩阵现状

三、系统与数据资产现状（5-8页）
   3.1 核心系统清单和功能
   3.2 数据架构图（现状）
   3.3 数据资产盘点（核心表/字段数量）
   3.4 数据流向图

四、数据质量现状（5-8页）
   4.1 质量问题总体评估
   4.2 各系统/各域质量得分
   4.3 TOP 10数据质量问题
   4.4 质量问题根因分析

五、数据标准现状（3-5页）
   5.1 现有标准清单和覆盖范围
   5.2 标准执行情况
   5.3 标准缺失领域

六、监管合规现状（3-5页）
   6.1 监管报送体系（EAST/1104等）
   6.2 报送数据质量
   6.3 历史处罚和整改情况

七、能力成熟度评估（3-5页）
   7.1 DCMM八大能力域评估结果
   7.2 与目标等级（如4级）的差距分析
   7.3 改进优先级矩阵

八、改进建议与实施路线图（5-8页）
   8.1 总体改进策略
   8.2 分阶段实施路线图
   8.3 资源需求估算
   8.4 风险与应对

附录：
   附录A：访谈纪要汇总
   附录B：系统走查详细记录
   附录C：数据质量抽样详细数据
   附录D：引用资料清单
```

**格式**：Word报告（30-50页）+ PPT摘要版（15页）

**关键要求**：
- 执行摘要放在最前面（高管只看这部分）
- 每页都要有标题、结论、建议（不要只摆事实）
- 用图表说话（架构图、流程图、柱状图、矩阵图）
- 问题要量化（"数据质量差"→"客户手机号合规率85%"）

## 💡 Step 1 关键技巧

| 技巧 | 说明 |
|:-----|:-----|
| 先访谈高管 | 获得高层支持和明确期望，后续工作更顺畅 |
| 用事实说话 | 不要只写"数据质量差"，要写"客户手机号合规率85%，影响3张监管报表" |
| 当天出纪要 | 访谈当天出纪要，趁热打铁，准确性高 |
| 保护被访者 | 访谈内容匿名处理，特别是批评性意见 |
| 抽样要随机 | 不要只挑好的数据检查，随机抽样才真实 |
| 报告先给发起人看 | 正式评审前先给项目发起人过目，避免评审时翻车 |

## ⚠️ Step 1 常见坑

| 坑 | 后果 | 如何避免 |
|:--|:-----|:--------|
| 资料收集不齐 | 调研不全面，方案有盲区 | 发正式邮件催办，抄送领导 |
| 访谈对象层级太低 | 得不到真实痛点和决策信息 | 确保访谈到部门负责人级别 |
| 被访者不说真话 | 收集不到真实问题 | 强调匿名保护，从闲聊切入 |
| 抽样范围太小 | 质量问题被掩盖 | 覆盖核心系统核心表，样本量≥1000 |
| 报告只摆事实 | 高管看不懂，不认可 | 每页都要有"So What"（意味着什么） |
| 报告太长 | 没人看 | 正文30-50页，附录取证，PPT摘要15页 |
