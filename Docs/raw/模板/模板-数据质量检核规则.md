## 一、检核规则设计原则

| 原则 | 说明 | 示例 |
|:-----|:-----|:-----|
| **由少到多** | 先配核心规则的 10 条，逐步增加 | 第一批：customer_id, customer_name, cert_type, cert_no, mobile |
| **阈值由松到紧** | 先设 90%，逐步提升到 95%、99%、100% | 手机号格式合规率：第 1 月 90% → 第 2 月 95% → 第 3 月 100% |
| **每条规则有唯一ID** | 便于追踪和管理 | Q001, Q002, Q003... |
| **每条规则有责任人** | 出现问题知道找谁 | Owner + Steward 双重责任 |
| **规则覆盖所有质量维度** | 完整性、准确性、一致性、及时性、唯一性 | 五个维度至少各配 2-3 条规则 |

## 四、告警级别定义

| 告警级别 | 定义 | 触发条件 | 通知方式 | 响应时限 |
|:-------:|:-----|:--------|:--------|:-------:|
| **严重** | 直接影响业务运营或监管合规 | 阈值 100% 的规则未达标 | 短信 + 企业微信 + 邮件通知治理团队 | 治理团队 1 小时内受理，分派后处理人 4 小时内响应 |
| **警告** | 影响数据质量但可容忍短期存在 | 阈值 90%-99% 的规则未达标 | 企业微信 + 邮件通知治理团队 | 治理团队 4 小时内受理，分派后处理人 1 个工作日内响应 |
| **提示** | 数据质量趋势预警 | 接近阈值但未触发 | 日报汇总 | 无需单独响应 |

## 五、检核规则 SQL 示例

### Q003：customer_id 格式合规

```sql
-- 检核 SQL
SELECT 
    COUNT(*) AS total_count,
    SUM(CASE WHEN customer_id RLIKE '^HB[1-59][0-9]{8}[0-9]{6}$' THEN 0 ELSE 1 END) AS fail_count,
    ROUND(100 * SUM(CASE WHEN customer_id RLIKE '^HB[1-59][0-9]{8}[0-9]{6}$' THEN 1 ELSE 0 END) / COUNT(*), 2) AS pass_rate
FROM t_customer
WHERE create_time >= DATE_SUB(CURRENT_DATE, INTERVAL 1 DAY);

-- 问题记录 SQL（用于问题台账）
SELECT customer_id, customer_name, create_time
FROM t_customer
WHERE create_time >= DATE_SUB(CURRENT_DATE, INTERVAL 1 DAY)
  AND customer_id NOT RLIKE '^HB[1-59][0-9]{8}[0-9]{6}$';
```

### Q009：身份证格式校验（GB 11643）

```sql
-- 检核 SQL
SELECT 
    COUNT(*) AS total_count,
    SUM(CASE WHEN cert_type = '01' AND f_check_idcard(cert_no) = 1 THEN 0 ELSE 1 END) AS fail_count,
    ROUND(100 * SUM(CASE WHEN cert_type = '01' AND f_check_idcard(cert_no) = 1 THEN 1 ELSE 0 END) / COUNT(*), 2) AS pass_rate
FROM t_customer
WHERE create_time >= DATE_SUB(CURRENT_DATE, INTERVAL 1 DAY);

-- 注：f_check_idcard() 为身份证校验函数，需自行实现或使用现有库
```

### Q021：手机号跨系统一致性

```sql
-- 检核 SQL
SELECT 
    COUNT(*) AS total_count,
    SUM(CASE WHEN a.mobile = b.mobile THEN 0 ELSE 1 END) AS fail_count,
    ROUND(100 * SUM(CASE WHEN a.mobile = b.mobile THEN 1 ELSE 0 END) / COUNT(*), 2) AS pass_rate
FROM t_customer a
JOIN t_credit_customer b ON a.customer_id = b.customer_id
WHERE a.create_time >= DATE_SUB(CURRENT_DATE, INTERVAL 1 DAY);
```
